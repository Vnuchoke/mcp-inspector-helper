# mcp-inspector-helper

Два скрипта для экспорта MCP-серверов из конфигурации OpenCode V2 в MCP Inspector
и сохранения списков инструментов и промптов каждого сервера.

- `opencode-to-inspector.py` преобразует JSON/JSONC из `mcp.servers` в `mcpServers`.
- `mcp-inspector-collect.sh` последовательно вызывает `tools/list` и `prompts/list`
  для всех серверов экспортированной конфигурации, проверяет ответы и повторяет
  неудачные запросы.

## Требования

Для экспорта нужен Python 3; сторонних Python-пакетов нет.
Для сбора нужны POSIX-совместимый `sh`, `jq`, `timeout` и команда
`mcp-inspector` в `PATH`. Inspector должен поддерживать CLI-параметры
`--config`, `--server`, `--method`, `--format json` и возвращать списки
в `result.tools` / `result.prompts`.

Локальным серверам также нужны их исполняемые файлы и зависимости;
удалённым — доступ к сети и необходимые учётные данные.

## Быстрый запуск

Выполняйте команды из каталога проекта.

1. Экспортируйте конфигурацию без подстановки секретов:

   ```sh
   python3 opencode-to-inspector.py
   ```

   Скрипт ищет сначала `~/.config/opencode/opencode.jsonc`, затем
   `~/.config/opencode/opencode.json`. Результат:
   `~/.mcp-inspector/opencode-mcp.json`.

2. Проверьте экспортированный файл локально. Для серверов с авторизацией
   заполните необходимые значения либо повторите экспорт с `--with-secrets`
   (см. раздел «Секреты и OAuth»).

3. Соберите списки:

   ```sh
   sh mcp-inspector-collect.sh
   ```

   **Скрипт запускает локальные серверы и подключается к удалённым.**
   Проверяйте команды и адреса конфигурации до запуска.
   Результаты сохраняются в `~/.mcp-inspector/results/`.

## Экспорт конфигурации

```sh
python3 opencode-to-inspector.py \
  --input /path/to/opencode.jsonc \
  --output "$HOME/.mcp-inspector/opencode-mcp.json"
```

| Параметр | Назначение |
| --- | --- |
| `--input PATH` | Явный путь к конфигурации OpenCode V2. |
| `--output PATH` | Путь результата; по умолчанию `~/.mcp-inspector/opencode-mcp.json`. |
| `--with-secrets` | Подставить `{env:NAME}` / `{file:PATH}` и сохранить учётные данные. |
| `--include-disabled` | Включить серверы с `disabled: true` или `enabled: false`. |
| `--force` | Разрешить замену существующего выходного файла. |

Поддерживаются `//`-комментарии, `/* ... */`-комментарии и завершающие запятые.
Минимальная структура входного файла:

```jsonc
{
  "mcp": {
    "servers": {
      "example": {
        "type": "remote",
        "url": "https://example.com/mcp",
      },
    },
  },
}
```

Адрес в примере условный; замените его адресом своего MCP-сервера.

### Что переносится

| OpenCode V2 | MCP Inspector |
| --- | --- |
| `type: local`, `command: [executable, ...args]` | `type: stdio`, `command`, `args` |
| `environment`, `cwd` | `env`, `cwd` |
| `type: remote`, `url`, `headers` | `type: http`, `url`, `headers` |
| `protocol: auto` / `2026-07-28` | `protocolEra: auto` / `modern` |
| `timeout.startup` / `timeout.execution` | `connectionTimeout` / `requestTimeout` |
| `oauth.client_id`, `client_secret`, `scope` | `oauth.clientId`, `clientSecret`, `scopes` |

По умолчанию используется `protocol: legacy`, без добавления `protocolEra`.
Для `timeout.catalog`, `oauth: false`, неизвестных OAuth-параметров и неизвестных
полей сервера выводятся предупреждения: точного переноса нет.
`codemode` не переносится. Отключённые серверы по умолчанию пропускаются;
с `--include-disabled` сборщик будет обращаться и к ним.

## Секреты и OAuth

Без `--with-secrets` значения всех заголовков, OAuth client secret и переменных
окружения с чувствительными именами заменяются пустыми строками. Строки
с `{env:...}` / `{file:...}` в обрабатываемых полях также заменяются целиком.
Такой экспорт может быть непригоден для подключения без ручного заполнения.

**Это не полное обезличивание:** литералы в URL, аргументах команды или переменных
окружения с нечувствительными именами могут остаться в файле.
Подстановки в `command`, `args` и `cwd` не выполняются.

Для экспорта с учётными данными:

```sh
python3 opencode-to-inspector.py --with-secrets --force
```

Команда заменяет существующий экспорт. Переменные окружения должны быть заданы,
а файлы из подстановок — доступны для чтения; иначе экспорт завершается ошибкой.
Выходной файл записывается атомарно с правами `0600`.
Не публикуйте конфигурацию, результаты или журналы без проверки содержимого;
текущий `.gitignore` не исключает такие файлы, если сохранить их в репозитории.

Сборщик по умолчанию задаёт `MCP_INSPECTOR_SECRET_STORE=file` и
`MCP_INSPECTOR_SECRET_KEY_FILE=$HOME/.config/mcp-inspector/secret.key`.
Для OAuth предварительно авторизуйтесь через интерактивный Inspector с теми же
настройками хранилища и ключа: экспорт не переносит OAuth-токены из OpenCode.

## Настройка сбора

Настройки передаются через переменные окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CONFIG` | `$HOME/.mcp-inspector/opencode-mcp.json` | Конфигурация Inspector. |
| `OUTPUT` | `$HOME/.mcp-inspector/results` | Каталог результатов. |
| `MAX_ATTEMPTS` | `3` | Число попыток для каждого метода каждого сервера. |
| `TIMEOUT_SECONDS` | `120` | Лимит одной попытки в секундах. |
| `RETRY_DELAY_SECONDS` | `3` | Пауза между неудачными попытками в секундах. |

```sh
CONFIG="$HOME/.mcp-inspector/opencode-mcp.json" \
OUTPUT="$HOME/.mcp-inspector/results" \
MAX_ATTEMPTS=2 TIMEOUT_SECONDS=60 \
sh mcp-inspector-collect.sh
```

Для каждого сервера создаются `tools.json` и `prompts.json` с полным JSON-ответом
Inspector. Диагностика пишется в `tools.error.log` / `prompts.error.log`;
пустой журнал после успешного запроса удаляется.

**Повторный сбор удаляет прежний результат каждого обрабатываемого метода
до запроса**, даже если новый запрос завершится ошибкой. Для сохранения истории
указывайте новый `OUTPUT`. Каталоги серверов, удалённых из конфигурации,
автоматически не очищаются.

Пустой список считается успешным ответом. Неподдерживаемый сервером метод
считается ошибкой и повторяется. Итог `OK` / `FAILED` считает пары
«сервер + метод», а не серверы. Код завершения — `0`, если все пары успешны,
и ненулевой при ошибках; для конфигурации без серверов — `0` и `OK=0, FAILED=0`.
